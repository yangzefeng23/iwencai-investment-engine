四种分析模式

覆盖投资决策全生命周期 · 情绪刹车优先执行 · 每种模式有固定触发词、数据编排与输出格式

🛑

情绪刹车（全局前置）：任何模式进入分析前，优先检测追涨冲动 / 恐慌抛售 / FOMO / 从众等情绪信号。检测到时先暂停，要求用户回答「把价格涨跌忽略掉，只看基本面，你还会这样判断吗？」，等用户理性确认后再继续。

Mode A

持仓复盘

Portfolio Review
触发：「复盘 / 持仓情况 / 看看我的仓」

全量持仓健康诊断，三色信号（🟢🟡🔴）综合评估行情、财务、机构三维度，联动历史记录。

用户输入持仓列表（标的 + 比例，可选均价/盈亏）
每只标的循环调用：market / finance / insresearch
yuque_search 检索该标的历史记录注入上下文
输出健康度评估表 + 持仓整体小结
hithink-market-query hithink-finance-query hithink-insresearch-query
Mode B

买卖决策

Trade Decision
触发：「买 / 卖 / 加仓 / 止损 / 要不要」

单一标的操作判断，五维分析框架按需展开 2-4 个维度，必写最强反对意见，结合语雀历史逻辑。

情绪刹车 + yuque_search 历史操作记录（最关键）
market（52周分位）/ finance（PE/PB/PEG）/ insresearch
announcement-search 近期公告 + news-search 催化剂
输出综合判断（支持/谨慎/反对）+ 必写最强反对意见
五维分析框架 announcement-search news-search
Mode C

宏观分析

Macro Analysis
触发：「宏观 / 政策 / 消息影响 / 大盘」

宏观事件传导链分析，覆盖持仓所在行业的资金流向与估值分位，联动历史相似宏观应对记录。

yuque_search 相似宏观环境下历史应对记录
macro-query 指标序列 + zhishu-query 指数反应
sector-selector 持仓行业资金流向（最多3个）
news-search 机构解读 + report-search 策略研报
输出传导链 + 持仓影响表 + 建议动作优先级
hithink-macro-query hithink-sector-selector report-search 数据管道：references/mode-c-data-pipeline.md
Mode D

个股研究

Stock Research
触发：「研究 / 深挖 / 分析 / 生成研报」

最全面的分析模式，10 步数据编排，从基础资料到机构评级全维度覆盖，生成标准化研究报告。

basicinfo 基础资料 + market 行情全貌
finance × 3（利润表 / 资产负债表 / 估值分位）
insresearch 机构评级 + announcement 近期公告
report-search 深度研报 + news-search 近期新闻
sector-selector 行业背景 + yuque 历史记录
10步数据编排 hithink-basicinfo-query report-search 数据管道：references/mode-d-data-pipeline.md 报告模板：assets/mode-d-report-template.md
五维分析框架（Mode B 专用，选取 2-4 个最相关维度）
Dim 01
业务理解与护城河
公司靠什么赚钱？品牌/成本/网络效应/牌照壁垒是什么？
Dim 02
估值与安全边际
PE/PB/PEG 历史分位，当前价格在 52 周区间哪个分位？
Dim 03
仓位合理性
单标的上限 20-25%，超 30% 先停止加仓，加仓理由检验
Dim 04
情绪隔离
触发器是基本面还是价格信号？近因偏误 / 锚定效应检测
Dim 05
持有逻辑检验
当初买入逻辑现在还成立吗？空仓测试：重来还会买吗？

ADR 设计决策

Architecture Decision Records · 关键架构决策记录，说明背景、选项与理由 v1.0

ADR-01 持仓数据获取：手动输入 vs API 自动拉取 Accepted ▾
背景

需要获取用户持仓数据（标的名 + 比例 + 可选均价）作为分析输入，可通过券商 API 自动拉取或用户每次手动输入。

选项对比
采用手动输入：零摩擦上手，无需配置任何 API token；每次粘贴时自然形成对持仓的主动审视；数据不经任何第三方接口传输，安全性最高。
拒绝券商 API：需配置 OAuth/token，各券商接口差异大维护成本高；账户数据安全风险；与轻量化设计约束冲突。
决策

采用手动输入。轻量化目标优先，不为自动化牺牲安全性与上手体验。每次手动输入也是一次对持仓的主动确认。

ADR-02 金融市场数据获取：直接调用 API vs 通过 Skills 调用 Accepted ▾
背景

investment-engine 需要拉取行情/财务/宏观等数据，可在 SKILL.md 中直接编写 Python 脚本调用 API，也可通过已有的 iwencai Skills 间接调用。

选项对比
采用通过 iwencai Skills 调用：各 Skill 封装了数据查询能力和错误处理逻辑，investment-engine 只负责编排，关注点分离，易于维护和扩展。
拒绝直接在 investment-engine 层写脚本：导致数据获取逻辑与分析逻辑耦合，修改 API 端点时需要同时改多处，违背单一职责原则。
决策

强制约束：所有金融市场数据必须通过项目内 iwencai Skills 调用，investment-engine SKILL.md 只负责编排顺序，不编写 API 调用脚本。

ADR-03 语雀写回：自动写入 vs 用户确认后写入 Accepted ▾
背景

分析完成后是否将结果自动写入语雀知识库？自动写入体验流畅，但可能污染知识库质量，引入大量低价值内容。

选项对比
采用用户确认写入：分析完成后提示用户是否保存，用户主动决定内容质量，知识库由人把关。语雀是「精华知识库」而非「操作日志」。
拒绝自动写入：体验流畅但引入大量低价值内容，长期导致知识库膨胀、信噪比下降，历史经验检索效果变差。
决策

所有写入必须用户确认。写入门槛是语雀知识库保持高质量的核心机制。

ADR-04 情绪刹车：后置校验 vs 前置拦截 Accepted ▾
背景

用户发出买卖指令时往往夹杂情绪（追涨/恐慌/FOMO）。是在分析完成后在结论部分提示情绪风险，还是在分析开始前先拦截确认？

选项对比
采用前置拦截：检测到情绪信号立即暂停，先输出情绪隔离提问，等用户用理性语言重新描述判断后再进入分析。防止用带有情绪的前提条件污染后续分析。
拒绝后置提示：分析完后说「请注意你可能有情绪偏差」。用户已经看到分析结论，确认偏误会让他们倾向于忽略提示，实际效果差。
决策

情绪刹车作为全局前置步骤，在任何模式的数据拉取之前执行，是分析流程的第一个节点。

ADR-05 买卖决策分析维度：全写五维 vs 按场景选取 2-4 维 Accepted ▾
背景

Mode B 有五个分析维度，是每次都全部展开，还是根据用户的具体情况选取最相关的维度？

选项对比
采用按场景选取 2-4 维：首次买入未知标的重点写业务理解；加仓已持有的重点写持有逻辑检验；检测到情绪信号重点写情绪隔离。输出更精准，避免千篇一律。
拒绝全写五维：每次分析结构相同，篇幅冗长，用户阅读成本高；很多维度对特定场景并不相关，反而降低分析质量的感知。
决策

强制要求 2-4 个维度，禁止每次都全写。SKILL.md 明确标注每个维度的「适用场景」，由 Claude 根据用户情况自主选择。
