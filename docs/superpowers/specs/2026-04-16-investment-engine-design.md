## 一、背景与目标

### 问题

投资者日常分析面临三类信息孤岛：

1. **持仓数据**：分散在各券商 App，缺乏统一分析视角
2. **市场数据**：行情/指标/资讯散落多处，拉取繁琐
3. **个人知识**：踩坑经验、操盘心法记在语雀里，分析时无法自动关联

### 目标

构建一个可以串联三类信息、实时分析、持续沉淀的投资交易分析引擎，核心约束：

- **轻量优先**：不引入独立系统、不搭数据库、不做持续部署，所有能力通过 Claude 配置文件实现
- **效果优先**：分析质量高于流程简洁
- **可持续沉淀**：每次分析都有机会反哺语雀知识库，形成正循环
- **数据获取约束**：所有金融市场数据统一通过调用项目内已有的 iwencai Skills 获取，不编写脚本直接调用 API

## 四、四种分析模式

### 模式 A：持仓复盘

**触发词**：复盘、持仓情况、仓位健康、看看我的仓

**数据收集**：用户输入持仓列表（标的名 + 比例，可选均价/盈亏）；信息不全时主动询问。

**数据编排（对每只持仓循环）**：

| 步骤 | Skill | 查询内容 |
|------|-------|---------|
| 1 | `hithink-market-query` | 最新价、涨跌幅、主力资金流向 |
| 2 | `hithink-finance-query` | ROE、负债率、净利润同比 |
| 3 | `hithink-insresearch-query` | 最新评级、目标价 |
| 4 | `yuque_search` | 该标的在 invest-kb 的历史记录 |

**输出结构**：

```
【{标的名} — 健康度评估】

| 维度 | 数据 | 信号 |
|------|------|------|
| 行情 | 最新价 X，今日 ±X%，主力净流入 X 亿 | 🟢/🟡/🔴 |
| 财务 | 净利润同比 ±X%，ROE X%，负债率 X% | 🟢/🟡/🔴 |
| 机构 | X 家买入/增持，目标价 X 元 | 🟢/🟡/🔴 |
| 仓位 | 占比 X%，均价 X，盈亏 ±X% | 🟢/🟡/🔴 |

历史记录（语雀）：{最近一条记录标题，若无则"暂无记录"}
持有逻辑：{当前基本面是否支持继续持有，一句话}

---

【持仓整体小结】
- 整体健康度：{高/中/低}
- 需重点关注：{1-2 个风险最高标的 + 具体原因}
- 稳健持有：{无需操作的标的}
- 建议下一步：{具体行动}
```

信号颜色：🟢 正常/积极 ｜ 🟡 中性/关注 ｜ 🔴 异常/警戒

### 模式 B：买卖决策

**触发词**：买、卖、加仓、减仓、清仓、止损、要不要、该不该

**前置：情绪刹车**

检测到情绪信号（亏损痛苦/追涨冲动/恐慌抛售）时，优先执行：
> 「先停一下。这个判断的触发器是财报/新闻（基本面信息），还是最近的价格变动？把最近的价格涨跌忽略掉，只看基本面，你还会有同样的判断吗？」

等用户回答后再继续。

**数据编排**：

| 步骤 | Skill | 查询内容 |
|------|-------|---------|
| 1 | `hithink-market-query` | 最新价、52周高低、近期涨跌幅、主力资金 |
| 2 | `hithink-finance-query` | PE/PB/PEG、近三年收入/利润增速、ROE |
| 3 | `hithink-insresearch-query` | 机构评级分布、目标价区间 |
| 4 | `announcement-search` | 近期重大公告 |
| 5 | `news-search` | 近期催化剂或利空事件 |
| 6 | `yuque_search` | 该标的的历史操作记录（最关键） |

**五维分析框架**（每次选取最相关的 2-4 个维度展开，不全写）：

**维度一：业务理解与护城河**
- 公司靠什么赚钱？收入来源是否稳定、可预期？
- 护城河类型：品牌溢价、成本优势、网络效应、转换成本、牌照/资质壁垒
- A股注意：行业政策风险、国企/民企属性对估值上限的影响
- 场外基金：基金经理的投资框架是否清晰？历史业绩来自可重复能力还是运气？

**维度二：估值与安全边际**
- 个股：PE（与历史均值和行业对比）、PB（重资产）、PEG（成长股）、自由现金流收益率
- 价格位置：当前价格在 52 周区间的分位，距离合理估值有多少折扣？
- 场外基金：估值百分位（低于 30% 才值得积极加仓，高于 70% 需谨慎）
- 港美股：参考国际同业 PE 对比，注意汇率风险

**维度三：仓位合理性**
- 单一标的上限：核心仓优质股不超过总资产 20-25%，机会性标的不超过 5-10%
- 加仓逻辑检验：是估值更便宜了（合理），还是想摊低成本（危险信号）？
- 超仓预警：某标的已超过总资产 30%，无论基本面多好，先停止加仓

**维度四：情绪隔离**
- 触发器检验：判断来自基本面信息，还是价格变动？
- 常见陷阱：近因偏误（因最近涨跌改变长期判断）、锚定效应（以买入价为"正确价格"）、处置效应（过早卖出盈利标的、过久持有亏损标的）

**维度五：持有逻辑检验**
- 已持有：当初买入的核心逻辑现在是否仍成立？逻辑已改变 → 无论盈亏都应重新评估
- 首次买入：核心买入理由是否已被当前价格充分反映？
- 空仓测试：今天清空重新分配，还会买这个标的吗？买多少？
- **语雀历史**：检索该标的的历史操作记录，当前决策与历史逻辑是否一致？

**输出结构**：

```
【买卖决策分析】{标的名} — {操作意向}

【情绪刹车】（若触发则在此输出，否则省略）

【分析】（仅展开 2-4 个最相关维度）

**{维度名}**
{2-3 句，数据 + 判断}

**{维度名}**
{2-3 句，数据 + 判断}

【综合判断】支持 / 谨慎 / 反对
{一句话核心理由}

【最强反对意见】（必写，即使综合判断是"支持"）
{当前操作最可能出错的场景}
```

## 五、语雀集成规范

### 知识库结构

```
{YUQUE_NAMESPACE}
└── 投资分析资产库/          ← 首次写入时若不存在则新建
    ├── 持仓复盘/
    ├── 买卖决策/
    ├── 宏观分析/
    └── 个股研究/
```

**文档标题格式**：`{YYYY-MM-DD} {模式} {关键词}`

关键词规则：
- 持仓复盘：列出主要标的（最多 3 个，超出用「等N只」）
- 买卖决策/个股研究：标的名称
- 宏观分析：事件核心关键词（5 字以内）

### 分析前检索

每种模式在进入分析前，统一执行语雀检索：

```
工具：mcp__yuque-mcp__yuque_search
参数：
  q:     "{标的名 或 宏观关键词}"
  type:  "doc"
  scope: "{YUQUE_NAMESPACE}"
结果处理：
  - 有结果：取最相关 2-3 条的标题 + 摘要 + 日期，注入分析上下文
  - 无结果：标注「知识库暂无相关记录，本次为首次分析」，不影响分析流程
```

### 分析后写回流程

分析完成后统一询问：「是否保存到语雀知识库？」用户确认后执行：

**Step 1 — 检查目录结构**
```
工具：mcp__yuque-mcp__yuque_get_toc
参数：namespace = "{YUQUE_NAMESPACE}"
目的：检查「投资分析资产库」和对应模式子目录是否已存在
```

**Step 2 — 按需创建缺失节点**
```
工具：mcp__yuque-mcp__yuque_update_toc
若「投资分析资产库」不存在 → 新建 group 节点
若对应模式子目录不存在 → 在其下新建子 group 节点
```

**Step 3 — 新建文档**
```
工具：mcp__yuque-mcp__yuque_create_doc
参数：
  book_id: {从 Step 1 获取}
  title:   "{YYYY-MM-DD} {模式} {关键词}"
  body:    {本次分析完整 Markdown 内容}
  format:  "markdown"
```

**Step 4 — 挂载到目录**
```
工具：mcp__yuque-mcp__yuque_update_toc
将新文档节点移动到对应模式子目录下
```

**Step 5 — 确认反馈**
- 成功：展示文档 URL
- 失败：输出完整 Markdown 供手动复制，说明失败原因，不静默失败

### 时间规范

所有时间统一使用**北京时间（UTC+8）**显示，包括文档标题日期、检索结果时间字段。MCP 接口内部若需 UTC 参数，调用前自动换算，对用户完全透明。
